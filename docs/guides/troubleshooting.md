# Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `make up` fails with "port is already allocated" or "address already in use" | Another service owns 4210, 4230, 4242, 4250, 4266 or 4279 | Set `SR_WEB_PORT`, `SR_API_PORT`, `SR_PG_PORT`, `SR_MOCK_LLM_PORT`, `SR_FLOCI_PORT` or `SR_REDIS_PORT` in `deploy/compose/.env`, then `make up` again |
| `make up` stops with "run `make env` first" | `deploy/compose/.env` is missing a required secret (an old or hand-written file) | Delete `deploy/compose/.env` and run `make env` (or `make up`, which runs it) |
| `make demo` fails with "service \"api\" is not running" | The stack is not up; `make demo` runs inside the api container | `make up` first, then `make demo` |
| `make demo` prints "demo data already present; skipping" | It only seeds an empty database | Expected. `make down` deletes the volumes; `make up && make demo` seeds again |
| Sign-in fails with the demo password | The password is the random `DEMO_PASSWORD` that `make env` wrote, not `RouterDemo2026` (that is only the fallback when `seed-demo` runs with no `DEMO_PASSWORD`) | `grep DEMO_PASSWORD deploy/compose/.env`. If `.env` was regenerated after seeding, the old password still applies: `make down && make up && make demo` |
| "Too many sign-in attempts from this address" or "Too many failed attempts" | Per-IP throttling and per-account lockout on the sign-in route | Wait a few minutes. An owner can reset a password with `smartrouter create-owner --email <email>` |
| 401 `invalid_api_key` | No key, a malformed key, or a key from another install (keys look like `tsr_<prefix>_<secret>`) | Send `Authorization: Bearer tsr_...` with a key from this install's API keys page. `make down` deletes keys with the database |
| 404 `model_not_found` | `model` is not `auto`, `auto:<policy>` or a configured alias (aliases are case sensitive) | `GET /v1/models` lists what the key can send |
| 404 `policy_not_found` | The policy in `auto:<name>`, the `x-smartrouter-policy` header or the project's default does not exist or is disabled, or no policy is marked default | Check the Policies page; set one policy as the default |
| 422 `no_eligible_model` | Every model was filtered: missing capability (tools, vision, JSON), context window, allowlist or exclusions, cost or latency ceiling, open circuits, or the quality floor with `on_no_eligible: reject` | `details.candidates` gives each model's reason. Run the same request in the Simulator, then relax the policy, add a capable model, or close a circuit |
| Every `auto` request goes to the same expensive model | The quality table is empty, so models are ranked by tier priors (advanced 0.9, fast 0.72, low-cost 0.66, local 0.6). With a floor of 0.8 only advanced models qualify | Run a benchmark (Benchmarks page or `make benchmark`). The Models page, Quality tab, shows "Nothing measured yet" until then, and the decision drawer shows `quality_source` as `prior` |
| A new model is never chosen | It has no benchmark scores yet, so its tier prior is below the policy's floor, or it is disabled, or its endpoint is disabled | Re-run the benchmark; check the model and endpoint are enabled |
| A model is skipped with "circuit open: recent failures" | Its upstream failed repeatedly (5 in a row by default, or a 50% error rate over 5 minutes) | Fix the provider. The circuit probes again after `BREAKER_COOLDOWN_S` (30 s); to close it now use Models, **Close circuit now** ([operations.md](operations.md#reset-a-circuit)) |
| A circuit stays open although the provider is back | The worker's health probe cannot reach the endpoint's model listing, so it keeps counting failures | Check the endpoint's base URL and key with **Test connection** on the Endpoints page |
| 502 `all_models_failed` | Every candidate failed, or the first failed and the policy has fallback off | `details.attempts` lists each model with its outcome and status. Check the Models page for health |
| 429 `upstream_rate_limited` | Exactly one model was called and its provider answered 429: a pinned model, a policy with fallback off, or a routed request with no other candidate left to try | Back off for the `Retry-After` seconds (passed on from the provider, `1` when it sent none) and retry. To have SmartRouter move on to another model instead, send `model="auto"` with a policy that has fallback on |
| A model is skipped with "circuit opened after ranking" | Its circuit opened between ranking and the call (another request's failures, or the worker's probe) | Expected: the request moves on to the next candidate. A pinned model is still called |
| 400 `endpoint_url_blocked` | The endpoint's host resolves to a link-local or cloud metadata address (`169.254.0.0/16`, `fe80::/10`, `fd00:ec2::254`), an unspecified, multicast or reserved address, or a loopback or private address while `ENDPOINT_ALLOW_PRIVATE=false`. Also returned when the host cannot be resolved from the API | Use the provider's public URL. For a model on your own network (Ollama, vLLM), keep `ENDPOINT_ALLOW_PRIVATE=true` (the default). Metadata and link-local addresses cannot be allowed |
| 400 `api_key_required` | The endpoint update changes its host, and the request carries no `api_key` | Send the endpoint's API key in the same request (paste it again in the dashboard). A stored key is never sent to a new host |
| 404 `not_found` from `POST /v1/feedback` | The `request_id` is not one SmartRouter routed: it is checked against the decision log, then against a marker the gateway keeps for a day, so feedback sent right after the request works | Send the `x-smartrouter-request-id` response header, not the upstream's `id` or `x-request-id`. Feedback on a request older than a day whose decision was never written (no worker ran) is refused |
| 402 `budget_exceeded` | A TokenShield endpoint refused on budget, and the policy has `budget_downgrade` off or no cheaper eligible model exists | Expected behaviour. Raise the budget in TokenShield, or enable budget downgrade on the policy |
| A benchmark stays "Queued..." | No worker is running, so nothing reads the queue | `make ps` and `make logs SERVICE=worker`; restart with `make up`. The run starts as soon as a worker is up |
| A benchmark run shows failed | An error during the run (for example an unknown model name in `--models`) | The run's error is stored with it; `make logs SERVICE=worker` shows the trace |
| A benchmark run failed with "stopped before it finished" | It was still running after `BENCHMARK_STALE_AFTER_S` (2 hours): the worker running it crashed or was redeployed | Start the run again. Raise `BENCHMARK_STALE_AFTER_S` if a real suite on slow providers takes longer |
| 503 `dependency_unavailable` when starting a benchmark | Redis was down, so the run could not be queued; it is marked failed rather than left queued | Check Redis (`make ps`, `GET /readyz`), then start the run again |
| 404 "expired" when downloading a benchmark's answers | The run is older than `BENCHMARK_RESULTS_DAYS` (365), so its results file has been deleted | Run the benchmark again. The run's summary stays on the Benchmarks page |
| Decisions appear late or not at all, Overview is flat | No worker is draining the decision stream, or rollups have not run yet (they aggregate closed hours every minute) | Start the worker (`make logs SERVICE=worker`). The Decisions page reads raw decisions; Overview reads hourly rollups |
| Dashboard shows "Cannot find module './NNN.js'" or stale pages during `pnpm dev` | A stale `.next` folder, often from a `next build` run while `next dev` was live | Stop `pnpm dev`, run `make clean` (removes `apps/web/.next`), start again. Note `pnpm dev` uses port 4210 like the Compose web service: stop one or change the port |
| `make up` waits a long time on the `terraform` service, or it fails with connection errors | Floci is not ready yet, or its volume holds state from an interrupted run | `make logs SERVICE=floci`. If it keeps failing, `make down` (wipes Floci and Terraform state together) and `make up` |
| `make test-matrix` says "Floci is not reachable" | The stack is not running | `make up` first |
| `make tf-aws-on-floci` fails to start its emulator | Port 4296 is taken | `TF_FLOCI_PORT=<free port> make tf-aws-on-floci` |
| Integration tests refuse to run | The database name lacks `test`, or the host is not local | Use `TEST_DATABASE_URL` pointing at a `*_test` database; `ALLOW_REMOTE_TEST_DB=true` for CI hosts |
| API refuses to start: "unsafe production configuration" | `ENVIRONMENT=production` with development secrets, equal `SESSION_SECRET` and `API_KEY_PEPPER`, or `AWS_ENDPOINT_URL` set with `SMARTROUTER_CLOUD=aws` | Fix the values the message names ([configuration.md](configuration.md#production-boot-guards)) |
